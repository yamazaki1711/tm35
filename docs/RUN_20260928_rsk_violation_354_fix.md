## 4. Предотвращение повторения

### 4a. Матчер — порог отказа от молчаливого закрытия

Новая константа `RSK_CLOSURE_REVIEW_THRESHOLD = 0.40` (main.py) —
НАМЕРЕННО ниже старого `RSK_MATCH_CANDIDATE` (0.55): это не «похоже
достаточно, чтобы посчитать кандидатом», а «недостаточно НЕпохоже, чтобы
закрывать молча». Перед тем, как отправить нарушение в «Снятые», КАЖДОЕ
проверяется ещё раз — без ограничения разделом, метрика — максимум из
`difflib.SequenceMatcher` (по символам) и нового `token_set_ratio()` (по
словам, устойчив к перестановке/сокращению формулировки, тот же алгоритм,
что `fuzzywuzzy.token_set_ratio`) — а также прямое совпадение печатного
номера. Если счёт ≥0.40 у ЛЮБОЙ позиции нового акта (независимо от того,
уже сопоставлена ли она с другим нарушением) — закрытие уходит в
`closure_review`, не в `removed`.

Проверено на реальной паре (`tools/test_rsk_parser.py`,
`test_violation_354_regression`): счёт «354» vs «4.3» = **0.407** — ниже
старого порога 0.55 (кандидатом не было бы вовсе), выше нового 0.40
(новая защита обязана сработать).

**Склейка через разрыв страницы** — реализована как дополнительная,
только информационная проверка: для каждой пары СОСЕДНИХ по документу
позиций нового акта склеенный текст тоже сравнивается со старым
нарушением; если склейка похожа ≥0.40 — попадает в список кандидатов с
пометкой (например «[2.14] …текст… + [2.15] …текст…»), но выбрать её как
привязку нельзя (в модели данных нет «одно нарушение = две позиции
акта») — это сигнал человеку присмотреться, разрешается только ручной
правкой в БД. Ограничение указано явно, не скрыто.

### 4b. Предпросмотр — «Проверить перед снятием»

`_rsk_build_import_result()` — новая категория `closure_review` (плюс
`reactivated` для явного «оставить активным без привязки»). Экран —
новая плитка и таблица (три колонки: снимается/похоже на/решение),
выпадающий список на каждую строку: «Снято — это другое нарушение» /
«То же нарушение, что п. N» (только для позиций акта, ещё не занятых
другим уверенным совпадением — если позиция уже сопоставлена, это
видно как «уже сопоставлен с №X», не предлагается к выбору) / «Не
снято — оставить активным (без привязки к пункту)». Ни одно
неразрешённое `closure_review` не даёт подтвердить импорт — та же
дисциплина, что уже была у неоднозначных соответствий («resolve_<i>»).

Ссылка «То же нарушение» технически становится обычным `override` для
матчера (`overrides[индекс_позиции] = violation_id`) — переиспользован
существующий механизм, не второй путь записи.

### 4c. Ручной инструмент в реестре

`/rsk/violation/{sys_no}` — для пользователей с правом `rsk:submit`:
- На **закрытом** нарушении — «Не снято — это то же замечание, что №…»
  (поле необязательное). Без номера — просто реактивация. С номером —
  `_rsk_merge_violation()`: позиции актов и связи с ИД дубликата
  переезжают на выживающее нарушение (при конфликте уникальности — не
  перезаписывают то, что уже есть у выжившего), обработка (слой 2)
  дубликата отбрасывается (выживает СВОЯ обработка того нарушения, на
  которое жмут кнопку), дубликат удаляется. Полностью аудируется
  (`audit_log`, `rsk_manual_reopen`, снимок дубликата до удаления).
- На **активном** нарушении — «Разъединить»: откатывает именно
  реактивацию (возвращает `is_active=false`, `closed_in_act_id` на
  последний акт) — не восстанавливает удалённый при объединении
  дубликат (это необратимо). Только слой 1 — «Устранено» по-прежнему
  правится в форме `/rsk/processing`, инструмент её не касается.

Проверено живьём на №354 (реальные HTTP-запросы, не эмуляция):
разъединить → снято, `closed_in_act_id=15`; не снято → снова активно,
`closed_in_act_id=null`. Оба шага — в `audit_log`.
