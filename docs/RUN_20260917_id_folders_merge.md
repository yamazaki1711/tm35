# TM-35 — «Папки» + «Реестр папок» слиты в одну страницу, 17.09.2026

Координатор нашёл клик по обоим пунктам меню ИД, ведущим на одну и ту же
таблицу `id_folder` под разными именами колонок.

## §1 — проверка на живом сайте до правки

Открыл все три страницы. Живое состояние совпало с таблицей из задания
буквально по всем восьми строкам:

- `/id-folders` («Папки») — колонки Название/Дата создания/Разделов/
  Оценка ПТО, ₽/Стадия/Сметная стоимость, ₽ (6 колонок).
- `/id-folders/registry` («Реестр папок») — колонки Номер папки/Дата
  формирования/Разделов/Стоимость, ₽/Подписант реестра передачи/Дата
  передачи в СДО/Статус (7 колонок), плюс фильтр статуса (с уже
  известным дублем «На проверке» — `checking`/`checking_all`),
  сортировка, «Скачать CSV».
- `/id-packages` («Разделы ИД») — действительно другая сущность
  (`id_form_row`, колонки Категория/Раздел/Ответственный/Статус/Дата
  статуса/Подписант РСК/Замеч. РСК) — не тронута.

Расхождений прод/задание не найдено — работал по прямому смыслу
задания, без корректировок.

## §2 — слияние

`/id-folders` — единственная страница со списком папок. Воронка папок,
«Деньги», «Разделы», «Последние переходы» — без изменений (не
относились к дублирующейся паре). В «Список папок» добавлены:
CSV-ссылка, четыре плитки-итога (переехали из реестра, две — под
переименованными подписями), форма фильтра+сортировки, восемь колонок
одним именем на каждую:

`Номер папки` · `Дата формирования` · `Разделов` · `Оценка ПТО, ₽` ·
`Сметная стоимость, ₽` · `Подписант реестра передачи` ·
`Дата передачи в СДО` · `Стадия`

Реестровская «Стоимость, ₽» (на самом деле `amount_rub`, тот же столбец,
что «Оценка ПТО, ₽») не пережила слияние — оставлено одно имя,
«Оценка ПТО, ₽», как более информативное (говорит, чья это оценка и
когда сделана).

Две плитки-суммы реестра переименованы под источник, тем же принципом:
- «Стоимость всех папок, ₽» (`sum(amount_rub)`) → **«Сумма оценок ПТО, ₽»**
- «Стоимость подписанных, ₽» (`sum(amount_smeta_rub)` подписанных) →
  **«Сметная стоимость подписанных, ₽»**

`compute_id_folder_stats()` внутри `id_folders_page()` теперь вызывается
один раз на страницу (было по разу в каждом из прежних двух маршрутов) —
`totals["amount_signed"]` берёт значение из того же вызова, что и
`stats`, не пересчитывает второй раз.

## §3 — ссылки, не сломанные слиянием

- `_id_folder_funnel.html`: `href="/id-folders/registry?status=…"` →
  `href="/id-folders?status=…"`. Проверено по всем пяти стадиям трубы на
  `/dashboard` и на `/id-folders` (см. §5 ниже) — каждая по-прежнему
  ведёт ровно на своё множество.
- `/id-folders/registry` — не удалён, стал 301-редиректом на
  `/id-folders` с сохранением `status`/`sort`
  (`urllib.parse.urlencode`). Проверено:
  `/id-folders/registry?status=signed&sort=asc` →
  `Location: /id-folders?status=signed&sort=asc` (301), итоговая
  страница отвечает 200 и приходит отфильтрованной.
- `/export/id-folders.csv` — URL и параметр `status` не менялись.
  Заодно выровнены подписи и порядок колонок CSV с колонками таблицы
  (было ещё и третье имя, «Стоимость (оценка), ₽», для того же
  `amount_rub` — снято); сам фильтр CSV (`formed`/`transferred`/иначе
  все) не трогал — вне периметра задания, работал так и до слияния.
- Пункт меню «Реестр папок» убран из `base.html`, `'id-folders-registry'`
  убран из списка `id_active`.
- Шаблон `id_folders_registry.html` удалён (мёртвый код — маршрут его
  больше не рендерит).

## §4 — дубль «На проверке» в фильтре

Два РАЗНЫХ множества назывались одинаково: `checking` (каноническая
стадия — только начата проверка, `id_folder_stage()`, та же стадия, что
подписана «Проверка» в колонке «Стадия» реестра) и `checking_all`
(слитое `transferred`+`checking`, то, что показывает труба). Множества
не менялись — только подпись `checking` в выпадающем списке: «На
проверке» → **«Проверка»** (то же слово, что уже стоит в колонке
«Стадия» для этой самой стадии — не изобретал новое имя, взял то, что
уже есть на экране). «На проверке» осталось за `checking_all`, как и в
трубе. Труба по-прежнему ссылается на `checking_all` через
`ID_FOLDER_PIPE_STAGE_REGISTRY_STATUS["checking"] = "checking_all"` —
не менялось.
