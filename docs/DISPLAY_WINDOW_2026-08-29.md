# Окно отображения графиков (01.08–28.11) — настройка, не хардкод

Решение координатора 29.08.2026: графики и диаграммы показывают
01.08.2026–28.11.2026, данные за июнь-июль остаются в БД нетронутыми.
Задача — только отображение. Конвенция отчёта — ПРОВЕРЕНО / НЕ
ПРОВЕРЕНО / ПРЕДПОЛОЖЕНИЕ.

## 1. Настройка, не хардкод

**ПРОВЕРЕНО.** Две строки в `app_setting` (тот же паттерн, что
`directive_deadline`/`object_timezone`): `display_window_start` =
`2026-08-01`, `display_window_end` = `2026-11-28`. Читаются через
`get_display_window()` (дефолты в коде — только запасной вариант, если
строк в БД вдруг не будет). Форма `/settings` дополнена блоком «Окно
отображения графиков» (та же вёрстка `dm-picker`, что у директивного
срока), с валидацией «начало не позже конца».

## 2. Где применено

**ПРОВЕРЕНО фактом на живом сайте** (скриншоты после hard-reload):

- **`/gantt`.** Ось `/api/gantt` зажата в `[display_window_start,
  display_window_end]` — навигация «пред./след.» упирается в границы,
  кнопки блокируются на краях (проверено вживую: 6× «пред.» от
  сегодняшней позиции реально останавливается на «01.08.2026 …
  30.08.2026», ось начинается с «01.08», кнопка «пред.» дизейблится;
  20× «след.» останавливается на «30.10.2026 … 28.11.2026», ось
  заканчивается «28.11», кнопка «след.» дизейблится). Ни одной даты
  июня/июля/после 28.11 на оси не было ни разу.
- **«Успеваем?» (`/status`) — интерпретация «Диаграммы и графики на
  „Обзоре“».** ПРЕДПОЛОЖЕНИЕ, зафиксировано явно: страница `/dashboard`
  («Обзор» в навигации) не содержит ни одного графика/диаграммы —
  только KPI-плитки и таблица (проверено — на странице нет ни одного
  `<svg>` с данными, ни `<canvas>`). Единственные реальные
  «диаграммы и графики» в системе (S-кривая, гистограмма численности,
  тренд прогноза) — на `/status` («Успеваем?»). Применил окно туда, а
  не додумывал структуру для `/dashboard`, которой там нет. Если
  имелось в виду что-то другое — уточнить.
  - S-кривая: нарастающий итог (`bcws_cum`/`acwp_cum`) считается по
    ВСЕЙ истории (иначе кривая обнулилась бы на 01.08, хотя реальный
    прогресс с июня никуда не делся — это было бы враньём, не просто
    обрезанной картинкой), но точки на график добавляются только
    внутри окна. Проверено скриншотом: ось начинается «01.08», кривая
    на этой дате уже НЕ с нуля (реально накопленное с июня значение),
    июньских/июльских дат на оси нет.
  - Гистограмма «Численность по дням» и «Тренд прогнозной даты по
    неделям» используют тот же (уже отфильтрованный) `series` —
    получают окно бесплатно, отдельно не трогал.
- **Плитка «Прошло срока».** `get_criticality_data()`: `project_start`
  теперь берётся из `get_display_window()` вместо `min(plan_start)` из
  `baseline_schedule` (было 01.07). Проверено фактом (не только по
  коду): `crit.project_start = 2026-08-01`, `elapsed_days = 28`
  (29.08−01.08), `total_days = 119` (28.11−01.08) — сверено вручную,
  совпадает день-в-день. Одна точка правки в `main.py` — тайл на
  `/dashboard` и коэффициент «Отставание от графика» там же берут это
  значение из одного и того же места, отдельно не дублировал.
- **Фильтры «по дням/неделям/месяцам».** НЕ ПРОВЕРЕНО в смысле «нашёл
  именно такой селектор» — сплошным поиском по всем шаблонам такого
  UI-элемента не нашлось нигде в системе. Единственный настоящий
  период-селектор — `sel-days` на `/gantt` (14/30/45/60 дней, размер
  окна показа, не диапазон дат) — он получает то же ограничение через
  тот же `/api/gantt` clamp, отдельно ничего не добавлял. Если
  координатор имел в виду что-то другое — не нашёл, уточнить, где.
