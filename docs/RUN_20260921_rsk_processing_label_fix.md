# TM-35 — /rsk/processing: клик по пустому месту больше не ставит «ПТО», чекбоксы сгруппированы по смыслу (задание координатора 21.09.2026)

## §1 — баг: `<label>`, оборачивающий целую группу

`backend/templates/rsk_processing.html:116` (было):

```html
<label style="display:block;...">Ответственный
  <div class="rsk-checkbox-row">
    <label><input type="checkbox" name="responsible_ids" ...> ПТО</label>
    ...
  </div>
</label>
```

Implicit label-binding уходит к первому labelable-потомку — здесь к
чекбоксу «ПТО». Внешний `<label>` — `display:block`, занимает всю
ширину формы и высоту строки чекбоксов; клик по пустому месту справа от
«Лаборатория» отмечал «ПТО». Ровно то, что было описано.

**Исправлено структурно**, не обработчиком клика: `<fieldset>` +
`<legend>` вместо оборачивающего `<label>` — `legend` физически не
может ничего «привязать» к себе, класс дефекта воспроизвести
невозможно. Тот же паттерн применён к блоку «Комментарий» рядом (одна
`textarea`, багом сам по себе не был, но той же формы — переведён на
отдельный `<label for=...>` вместо обёртки, для единообразия и на
случай, если рядом появится второй контрол).

### Вторая находка — `rsk_import.html:11`

```html
<label>Файл акта (PDF)
  <span class="file-input-row">
    <input type="file" ... id="act-pdf-input" class="file-input-visually-hidden">
    <label for="act-pdf-input" class="file-btn">Выбрать файл</label>
    <span class="file-name">...</span>
  </span>
</label>
```

Внешний `<label>` оборачивал `<span>` с input и ВЛОЖЕННЫМ `<label
for=...>` — невалидная вложенность плюс implicit binding к первому
labelable-потомку (сам input). Исправлено: внешняя подпись стала
отдельным `<label for="act-pdf-input">` (не обёрткой) — указывает на
тот же input явно, тем же штатным способом, что уже работал у кнопки
«Выбрать файл» рядом; обе подписи теперь корректно и независимо
указывают на один input через `for=`, ничего не вложено.

Дата-пикеры (`<label>Дата <span class="dm-picker">…`) не трогал — один
видимый контрол (текстовый input), hidden-инпут и кнопка календаря
(`tabindex="-1"`, не в списке labelable по определению задания) не
считаются — легитимная форма, не тот класс дефекта.

## §2 — перегруппировка по смыслу

Было: один `rsk-form-grid` на восемь элементов, `auto-fit` на трёх
колонках раскидывал «Отклонено РСК»/«Устранено» по случайным местам
сетки, «Устранено» — не рядом с «Дата снятия». Стало (каждая группа —
свой grid-контейнер, перенос на узких экранах не смешивает их):

1. `Физика` · `Проект` · `ИД` — один ряд.
2. `Условие снятия` · `Плановая дата снятия` — одна группа.
3. `Устранено` (чекбокс) · `Дата снятия` — одна группа, рядом.
4. `Отклонено РСК` — отдельно, не между списками.
5. `Ответственный` — `fieldset`, чекбоксы в один ряд (`.rsk-checkbox-row`,
   требование ТЗ 16.09.2026 — сохранено, не тронуто).
6. `Комментарий`, затем `Сохранить`.

Проверено на 1366×768, 1920×1080, 2560×1440 — `main { max-width:
1360px }` держит форму в одной ширине на всех трёх, группировка
идентична и читается верно на каждом (скриншоты ниже).

## §3 — новая проверка в `tools/ui_audit.py`

`label_scope`: для каждого `<label>` — число labelable-потомков
(`input:not([type=hidden])`, `select`, `textarea`) и вложенных
`<label>`. Больше одного контрола или хотя бы один вложенный `<label>`
→ провальная находка с именем страницы и текстом подписи.

До правки (прямой скрипт на `/rsk/processing?sys_no=382`, отдельно —
этот маршрут требует query-параметр, которого нет в списке маршрутов
`app.routes`, поэтому сплошной обход сайта его не проверяет без
точечного захода):

```
processing: [{"idx": 9, "controls": 4, "nested": 4, "text": "Ответственный ПТО ДПР строй-площадка Лаборатория"}]
```

Сплошной обход сайта (`tools/ui_audit.py`, маршруты без обязательных
query-параметров) до правки нашёл вторую находку сам:

```
label_scope: 3 (1 находка × 3 разрешения, /rsk/import, «Файл акта (PDF) Выбрать файл Файл не выбран»)
```

После правки — оба нуля, проверено раздельно (точечный скрипт для
`/rsk/processing?sys_no=382` → `[]`) и сплошным обходом (`label_scope`
отсутствует в категориях сайта вовсе). Итого хитов: **2 → 0**, как и
требовало задание.

## §4 — живая проверка: клик по пустому месту

`/rsk/processing?sys_no=382`, чекбоксы до клика: ПТО=true, ДПР=true,
строй-площадка=false, Лаборатория=false (реальные сохранённые данные
нарушения). Четыре клика по пустому месту внутри `fieldset` (правее
последнего чекбокса на той же строке, над строкой чекбоксов рядом с
legend, на самом тексте «Ответственный») — состояние чекбоксов не
изменилось ни разу, включая клик РЕАЛЬНОЙ мышью через `computer`, не
только синтетическим DOM-событием. Отдельно проверено, что клик по
самому чекбоксу «Лаборатория» по-прежнему переключает его — функция не
сломана, сломано было только пустое место. Ничего не сохранялось
(«Сохранить» не нажимался) — состояние чекбоксов в БД не менялось.
