## Правка

`/rsk` (`backend/templates/rsk_registry.html`): убран `<th>Снято</th>`
и ячейка `{{ r.closed_act_date|fmt_dmy... }}`. Обоснование координатора
— нарушение, отсутствующее в последнем акте, уже получает бейдж
«Снято» в столбце СТАТУС (`rsk_pseudo_status()` → `"closed"` при `not
is_active`), вторая колонка дублировала тот же факт датой закрывающего
акта.

`/export/rsk.csv` (`export_rsk_csv()`, `backend/main.py`): убрана та же
колонка из заголовка и из кортежа строки. Проверено — `rsk_registry.csv`
никем не читается, кроме самой этой функции и ссылки на неё в шаблоне
(`grep -rln "rsk_registry.csv\|rsk\.csv"` — только `main.py`), безопасно
снимать без стороннего эффекта. Экран и выгрузка снова совпадают по
набору колонок.

`closed_act_date` оставлен в `RSK_LIST_SELECT_SQL` (`ca.act_date as
closed_act_date`) — не читается больше ни в шаблоне, ни в CSV, но
JOIN на `rsk_act ca`/структурная модель закрытия (`v.is_active`,
`v.closed_in_act_id`, обновляются только импортом акта) не тронуты,
как и просило задание. Фильтр «Состояние → Снятые» (`state=closed` →
`not v.is_active`) читает флаг напрямую, не через `closed_act_date` —
работает без изменений, не проверялся заново отдельно (логика не
менялась).
