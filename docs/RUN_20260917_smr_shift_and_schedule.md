## §1 — меню «Ввод»: одна точка входа для факта дня

## §2 — экран смены: форма факта вместо «добавить работу»

удалён целиком вместе со страницей — второй копии формы не осталось.

Сохранение сразу видно в таблице ниже (та же перерисовка `load()`, что
у остальных ячеек экрана) — проверено вживую (см. §7).

## §3 — сроки в таблице и сама причина «график не обновляется»

Добавлены `Дата начала работ`/`Дата окончания работ` — инлайн в каждой
строке таблицы (виджет `dm-picker`, как везде в проекте; поскольку
строки таблицы перерисовываются AJAX-ом уже после `DOMContentLoaded`,
`datepicker.js` получил публичный `window.TM35_DATEPICKER.init()` —
раньше виджет инициализировался только на маршруте `DOMContentLoaded`,
динамически добавленная разметка не подхватывалась вовсе) и кнопка
`Обновить график СМР`.

**Причина разрыва — три несвязанных хранилища одного и того же
"планового срока"** (полный разбор в `KNOWN_ISSUES.md` §51):

| Хранилище | Писал | Читал |
|---|---|---|
| `baseline_schedule` | форма `/baseline` | `/status`, `/dashboard`, `/today` |
| `current_schedule` | только `/gantt` | только `/gantt` |
| `work.plan_finish_date` | форма `/form` | только сама форма + CSV |

Ввод факта писал в третье хранилище, которое не читал никто, кроме
самой формы — отсюда и «не обновляется». **Резолюция**: инлайн-поля
таблицы и модалка «Ввод факта» пишут в `current_schedule` — тем же
эндпоинтом, что уже использовал `/gantt` (`/api/gantt/schedule`,
логика вынесена в общую `_write_current_schedule()`, второй писатель не
заводился). `/status`/`/dashboard`/`/today`
(`get_criticality_data()`/`get_lookahead_works()`/
`get_critical_rule_works()`) переведены на `coalesce(current_schedule,
baseline_schedule)` — раньше читали только `baseline_schedule`, новый
срок туда не попадал вовсе. `work.plan_finish_date` не пишется больше
ничем (историю не переписывал), `/export/works.csv` переведён на тот
же `coalesce()`.

Сохранение — по уходу из ячейки (как остальные колонки), не только по
кнопке: кнопка `Обновить график СМР` — честный ручной пересчёт
отображения (перезагружает таблицу с сервера), не единственный путь к
корректности, как и требует задание («кнопка, которую нужно не забыть
нажать — тот же дефект с крышкой»).

## §4 — работы на 100% в выпадающем списке

Список работ для модалки «Ввод факта» (`/api/shift`, поле `work_rows`)
делится на два визуальных блока: обычный список и `<optgroup
label="Выполнены физически">` для работ с `fact_pct >= 100` — 55 из 174
на 17.09.2026, отсортированы после всех остальных, не пропадают из
выбора (проверено — процент всё ещё можно поправить, работа не
потерялась).

## §5 — Подрядчик: справочник уже был

Проверено ДО реализации: справочник `subcontractor` уже существует, и
`/api/gantt/subcontractor` уже делает ровно то, что просит задание —
ищет строку по имени, находит или создаёт, назначает на `work`
(`subcontractor_id`/`executor_type`), не на дневную запись (координатор
уже решил этот вопрос раньше, при работе над `/gantt`). Логика
вынесена в общую `_assign_subcontractor()`, вызывается и из
`/api/gantt/subcontractor`, и из нового `/api/shift/fact` — второй
копии не заводилось. Чекбокс «Подрядчик» + поле имени в модалке
работают ровно на этом пути; при выборе работы в модалке текущее
состояние (`executor_type`/имя субподрядчика) подгружается через
расширенный `/api/existing-entry`. **Судебное решение**: снятие
чекбокса НЕ снимает уже стоящее назначение — форма трогает подрядчика
только когда чекбокс отмечен и имя указано; полное «отвязать
подрядчика» заданием не описано явно, консервативный выбор — не делать
того, о чём явно не просили.

## §6 — «Смотреть»: что за чем стоит

- `/status`: убран `<h2>Отклонение от директивного срока по неделям</h2>`
  и `#trend-chart` — `status.js` уже проверял элемент на `null` перед
  отрисовкой, правка чисто в шаблоне.
- `/today`: убран блок «Ограничения к снятию» — но не просто убран.
  Проверка ПЕРЕД удалением показала: это была ЕДИНСТВЕННАЯ на весь
  сайт форма снятия/правки стоп-фактора (`POST /api/blocker/{id}`,
  поля «ожидаемая дата снятия»/«ответственный», кнопка «Снято») —
  `/blockers` (страница, которую задание прямо просит не трогать) её
  не имела вовсе, только создание + read-only реестр. Удаление стёрло
  бы способность вообще снимать стоп-факторы, тем самым дефектом, о
  котором задание явно предупреждает применительно к пункту меню.
  **Перенесено, не удалено**: та же форма (даты/ответственный/кнопка
  «Снято») добавлена в реестр `/blockers`, редирект
  `/api/blocker/{id}` исправлен с жёсткого `/today` на `/blockers`
  (единственный оставшийся отправитель). Проверено вживую (§7).
- Пункт меню `Почему отстаём` убран из «Смотреть» — только пункт,
  страница `/blockers` и `Ввод → Стоп-фактор` (`/blockers#blocker-form`)
  работают как прежде.
- Доклад без изменения (`KNOWN_ISSUES.md` §54): отдельная страница
  `/losses` с тем же заголовком `<h1>Почему отстаём</h1>`, ни из одного
  меню не открывается — решение за координатором.
