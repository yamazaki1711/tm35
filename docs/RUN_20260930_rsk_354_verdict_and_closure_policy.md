# РСК: полнота разбора акта 4183-162 (вердикт по №354) и пересмотр политики закрытия — 30.09.2026

Продолжение `docs/RUN_20260928_rsk_violation_354_fix.md` / `KNOWN_ISSUES.md`
§71. Прошлый заход закрыл вопрос «снято физически или нет» (координатор
подтвердил — нет), но не доказал строго, что парсер прочитал акт
ПОЛНОСТЬЮ: вывод «0 совпадений на 122 283 символа» опирался на ту же
экстракцию текста, чья полнота не была проверена отдельно — круговое
рассуждение. Задание этого захода — доказать полноту постранично, дать
точный вердикт (A/B), и отдельно пересмотреть политику автозакрытия.

## 1. Проверка полноты — постранично, а не по документу целиком

`pdfplumber`, файл `/app/uploads/rsk_acts/confirmed/4183-162.pdf`, 47
страниц:

| Проверка | Результат |
|---|---|
| Страниц с текстовым слоем | **46 из 47** — страница 46 (индекс, печатный номер «47», последняя) — 0 символов |
| `page.chars`/`.rects`/`.lines` на стр. 46 | все пустые |
| `page.images` на стр. 46 | **1** (единственный объект страницы) |
| Непрерывность нумерации «№ NNN Повторно» | 135 якорей, диапазон 3-387, без дублей; пропуски есть, но ожидаемые (несквозная нумерация между актами, не аномалия) |
| Совпадение якорей ↔ разобранных `sys_no` | 135 = 135, полное совпадение — сам алгоритм якорей/полос внутри `parse_act()` не терял ничего из того, что видел |
| Растеризация стр. 46 (`pypdfium2`, диагностика) + визуальный просмотр | читаемая строка «№ 354 Повторно... СИЗ (каски)... Просрочено на 306 к. дн.», затем «Общее количество нарушений - **136**» |

Разбор нашёл 135 позиций — акт заявляет 136. Расхождение ровно на одну
позицию — №354.

**Вывод — Вердикт A**: №354 присутствует в акте, РСК сама повторно
отметила его как неустранённое («Повторно», просрочка 306 к.дн.).
Причина пропуска — не текст, не похожесть, не логика якорей: последняя
страница акта физически не содержит извлекаемого текста (вложенное
изображение вместо текстового слоя), хотя все остальные 46 страниц —
нормальный текстовый PDF. Механическая, локальная находка, не системная
ошибка алгоритма.

Реактивация №354 (сделана 28.09.2026, `is_active=true`) остаётся верной
по факту, но её обоснование меняется: не «отсутствует в акте, оставлено
решением координатора», а «пропущено разбором, страница акта физически
не читается — по факту присутствия».

## 2. Побочная находка — позиция «4.5» (sys_no 56) обрезана

Текст той же позиции, идущей ПЕРЕД №354 в документе, обрывается в БД на
«...шифр 2020.069.3000-ТМ-ПОС-ПЗ, Изм. 6; п. 7.13» — без продолжения.
На изображении стр. 46 ПЕРЕД строкой №354 виден хвост именно этой цитаты
(«...СП 48.13330.2019 «Организация строительства»; ч. 6 ст. 52 ГрК РФ.»)
— та же страница-изображение оборвала конец «4.5», а не только унесла
целиком «4.6»/№354. Позиция «4.5» остаётся активной (не закрыта этим
актом) — обрезка касается только качества сохранённого текста, не
структурного статуса.

**REQUIRES COORDINATOR DECISION**: восстановить текст вручную по
изображению (транскрипция, не разбор — требует явной пометки в БД/логе
«восстановлено вручную по изображению страницы 46, не парсером») или
оставить обрезанным как есть с пометкой «требует проверки».

Проверено: ни одно из 16 нарушений, закрытых актом 15, не граничит со
страницей 46 (только «4.5»/56 и «4.6»/354 её касаются) — находка не
затрагивает остальные закрытия этого импорта.

## 3. Защита парсера — два новых жёстких отказа

`rsk_parser.py`:
- `find_image_only_pages(pdf)` — новая функция: страница (кроме
  титульной) с `extract_words() == []`, но `len(page.images) > 0` —
  флагуется. Картинка отличает «текст пропал» от «страница легитимно
  пуста» (у последней изображения не бывает). Результат —
  `checks["image_only_pages"]`.

`main.py`, `_rsk_hard_guard_errors()` — два новых отказа (до показа
предпросмотра, до записи):
- `image_only_pages` не пуст → «Страница(ы) N акта — вложенное
  изображение без текстового слоя...».
- `total_declared_in_act != len(records)` (когда итоговая строка акта
  распознана) → «Акт заявляет N, а разбор нашёл M...». Ловит и будущие
  случаи частичного (не полностью пустого) обрыва страницы, которые
  первая защита не поймает.

Проверено на самом файле 4183-162.pdf — `image_only_pages=[46]`, отказ
фактически срабатывает (не только на синтетике). `tools/test_rsk_-
parser.py`, тесты (г)/(д) — фейковые страницы, воспроизводящие ровно
находку (`page.chars=0`, `page.images=1`), и оба guard-условия отдельно.

## 4. Политика закрытия — пересмотрена (REQUIRES COORDINATOR DECISION из §71)

§71 оставляло открытым: порог 0.40 без учёта раздела отправляет 17 из 17
закрытий акта на подтверждение — подтвердить цену или пересмотреть.
Координаторское задание этого захода — не менять порог, а **сузить
условие автозакрытия**: закрывать молча теперь можно ТОЛЬКО если
(а) `rsk_processing.resolved = true` И (б) даже после чистки текста от
типовых нормативных фраз ни один пункт нового акта не набрал похожести
≥0.40. Не выполнено любое из двух — «Проверить перед снятием» (включая
`resolved=false` без единого кандидата — раньше закрылось бы молча).

**Боилерплейт-фразы** (`RSK_BOILERPLATE_PHRASES`, `main.py`) — посчитаны,
не придуманы: n-граммы слов, встретившиеся в ≥20% позиций ОБОИХ хранимых
актов (287 позиций всего), длинные варианты поглощены самым полным.
11 фраз — методика и полный список n-грамм до поглощения см. вывод
скрипта (не хранится в репозитории, воспроизводим по тем же двум актам
в БД) в конце этого файла, §6.

**Реплей акта 4183-162 «из состояния до импорта» новой политикой**
(методика: пул кандидатов = текущие активные + закрытые именно актом 15,
контент — из последнего `act_item` до акта 15; `tools/test_rsk_-
parser.py`, тест (ж)):

```
records: 135
removed (закрыто молча): 0
closure_review (на проверку): 17 — [100, 127, 151, 163, 164, 176, 218,
    224, 255, 327, 331, 354, 367, 376, 380, 384, 385]
```

**Гипотеза задания («16 закроются молча, №354 — на проверку») не
подтвердилась.** Факт: ВСЕ 17 уходят на проверку, как и по старой
политике — 0 изменений в числе. Причина — не брешь чистки (проверено
отдельно, тест (е): чистка исправно убирает цитаты СП/ГрК РФ), а то, что
похожесть этих 16 на другие позиции нового акта — СОДЕРЖАТЕЛЬНАЯ, не
шумовая: объект состоит из множества похожих по сути участков/камер/опор,
и инспектор описывает одинаковый по типу дефект («работы без
освидетельствования предыдущих работ») почти одним языком на разных
пикетах.

Пример — №331 (участок УТ15-УТ16, структура «УТ16») против пункта 2.10
нового акта (тот же участок, структура «КР3»): похожесть **0.994**,
тексты различаются практически только кодом структуры в скобке. Даже
человек не отличит «то же самое» от «другая структура» без взгляда в
исходный акт — это не шум для чистки, это реальная неоднозначность
объекта.

**Итог**: новая политика НЕ сократила число проверок для этого акта
(осталось 17 из 17), но убрала риск молчаливого закрытия неустранённого
— то, ради чего вводилась. Дальнейшее сокращение ручной нагрузки
(например, вырезание кодов пикетов/структур перед сравнением) —
отдельное решение с отдельным риском, не предпринято в этом заходе без
данных о накоплении по следующим актам.

**REQUIRES COORDINATOR DECISION**: принять текущий результат (100%
проверок, как и раньше, но теперь безопасно и осознанно) или заказать
более агрессивную нормализацию текста (риск спрятать настоящее отличие,
как это произошло бы с №354, если бы порог был выше).

## 6. Методика подсчёта боилерплейт-фраз (воспроизводимость)

N-граммы слов длиной 3-40, посчитана document frequency (число ПОЗИЦИЙ,
не вхождений, в которых встречается точная подстрока) по `content` всех
`rsk_act_item` двух хранимых актов (`act_id in (1, 15)`, `norm_literal()`
применена перед разбиением на слова). Порог — 20% от 287 позиций (57.4).
Из прошедших порог кандидатов длинные поглощают короткие (если короткая
фраза — подстрока уже выбранной длинной, короткая отбрасывается),
результат отсортирован по частоте. Список — `RSK_BOILERPLATE_PHRASES`
в `main.py`, с этим же обоснованием в комментарии рядом.
