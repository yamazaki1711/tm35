## §1 — «Стоимость»: одно слово, один расчёт, диагностика ДО правки

Прямой SQL по всем 20 папкам `id_folder`, скрипт прогнан в контейнере до
единой строки кода:

| Вопрос | Ответ |
|---|---|
| Папок с обеими колонками (`amount_rub` И `amount_smeta_rub`) заполненными | **0** |
| Из них расходящихся | **0** (тривиально) |
| `signed_date is not null` (подписано хоть когда-то) | **0** |
| `signed_date < 10.03.2026` (граница «Подписано ранее») | **0** |
| Пересечение «до границы» и КС-2 | **0** |

Колонки БД **не трогал** (не сливал, не перезаписывал) — только
интерфейсный ярлык. В интерфейсе везде теперь одно слово «Стоимость,
₽»; значение — `coalesce(amount_smeta_rub, amount_rub)` через
единственную функцию `id_folder_cost(folder)` в `main.py`. Прошёл по
всем местам, где раньше считалось значение папки в деньгах: список
`/id-folders`, карточка папки, CSV-экспорт, суммы воронки
(`compute_id_folder_funnel()`), денежные тайлы — нигде не оставил
второго выражения. `tools/check_consistency.py` (проверка «Стоимость,
₽…») сверяет сумму `id_folder_cost()` по списку с прямым SQL `coalesce`
— 0 расхождений.

Честный ноль на тайлах «Подписано ранее, ₽»/«Подписано по КС-2, ₽» —
задание прямо предвидело этот исход. `CLAUDE.md` упоминает ≈82 млн ₽,
закрытых по КС-2 на 08.04.2026 («Комплексный анализ ТМ-35», не
проверено независимо) — заведомо другое число, чем 0 в БД сейчас.
Расхождение не устранял и не подставлял вымышленное число вместо
честного нуля — запись в `KNOWN_ISSUES.md` §45, решение координатора.

## §2 — «Папки»: новый порядок секций, 6 колонок, дропдауны

Секции сверху вниз: **Деньги → Воронка папок по стадиям → Разделы →
Список папок** (было — Воронка → Деньги → Разделы). `/id-folders/registry`
как отдельная страница из этого захода уже не существовала (слито в
предыдущей задаче 17.09.2026) — редирект оставлен как есть, репointнут
на новую логику фильтра.

Таблица «Список папок» сведена к 6 колонкам одним именем каждая:
`Номер папки` · `Дата создания` · `Разделов` · `Стоимость, ₽` ·
`Подписант реестра` · `Статус`. Убраны: `Дата передачи в СДО`, вторая
денежная колонка, старая строка плиток-итогов над таблицей (два её
тайла были ровно тем дублированием, что убирает §1 — решение убрать
целиком, не переименовывать: задание не упоминает эту строку ни разу
среди явно перечисленных тайлов).

Два дропдауна одним блоком: `Статус` — ровно шесть значений (пять
стадий трубы через `ID_FOLDER_REGISTRY_STATUS_TO_PIPE_STAGE`, тот же
классификатор, что рисует саму трубу, плюс отдельное `Неподписано`),
`Сортировка по номеру` — без изменений. Дубль подписи «На проверке»
(из прошлой задачи, `checking`/`checking_all`) в новом списке не
воспроизведён — `checking` как отдельное значение фильтра тут не
участвует вовсе, задание требует ровно шесть перечисленных пунктов.

**Известная косметическая нестыковка** (`KNOWN_ISSUES.md` §46): в
списке нет пункта «Все» — при заходе без `status=` браузер визуально
подсвечивает первый пункт («Сформировано»), а таблица честно показывает
все 20 папок. Расхождение видно на экране (проверено), но добавлять
седьмой пункт сверх буквально заданных шести не стал без решения
координатора.

## §3 — пять денежных тайлов, идентичных на /dashboard и /id-folders

`Всего по контракту, ₽` · `Подписано ранее, ₽` (новый) ·
`Подписано по КС-2, ₽` · `Невыбираемый остаток, ₽` · `Остаток по
контракту, ₽`. Граница даты «Подписано ранее» — `10.03.2026`, хранится
в `app_setting['id_signed_before_boundary_date']`
(`migrations/037_id_signed_before_boundary.sql`, не буквальным числом в
коде — координатор может поправить прямым `UPDATE app_setting` без
деплоя). Папка, подписанная до границы, идёт в «Подписано ранее» и
явно исключается из «Подписано по КС-2» (`overlap_count` считает
пересечение отдельно, для отчёта — на 17.09.2026 равен 0, диагностика
§1). `Остаток по контракту, ₽` = контракт − подписано ранее − подписано
по КС-2 − невыбираемый остаток — закрывает `KNOWN_ISSUES.md` §42
(«два разных остатка»): формула и подпись теперь одна и та же на обеих
страницах, проверено сверкой отрендеренного HTML тайл-в-тайл
(`check_consistency.py`).

На «Папках» убраны целиком: `Ещё не подписано`, `Подписано ждёт сметной
стоимости`, `Ручной объём`, `Остаток в деньгах` — пять тайлов §3 теперь
весь денежный раздел на обеих страницах, других тайлов не осталось.

## Найдено и исправлено по пути (не было явно в задании, но входит в его периметр)

- **`status=signed` не фильтровал** — старые ссылки на бывший
  `/id-folders/registry?status=signed` (канонические стадии
  `ID_FOLDER_STAGES`, не совпадающие 1:1 с пятью значениями нового
  дропдауна) проваливались сквозь оба условия и показывали все 20
  папок вместо отфильтрованных. Это прямо ломало критерий приёмки §6.5
  (`status=signed&sort=asc` должен «прийти отфильтрованным»). Добавлен
  legacy-alias: если `status` — каноническая стадия
  (`formed`/`transferred`/`checking`/`signed`/`ks2`), не покрытая новым
  словарём, фильтруем через `id_folder_stage()`. Та же правка — в
  `export_id_folders_csv()`, для симметрии CSV/экрана.
- Флеш-сообщения формы «Стоимость после подписания» (`/api/id-folder/{id}/smeta`)
  всё ещё говорили «Сметная стоимость…» — экран, который грепом легко
  пропустить (текст появляется только после сабмита формы, не в
  статической разметке). Переименовано в тот же текст, что заголовок и
  подпись поля.
- `tools/check_consistency.py`: 4 проверки ссылались на удалённые поля
  `compute_id_folder_stats()` (`signed_folders_sum`, `awaiting_smeta_count`,
  `not_signed_count`, старая формула `money_remaining`) — упали бы
  `KeyError` при первом запуске после деплоя. Переписаны под новые поля
  (`signed_before_count`/`ks2_count`/`overlap_count`), плюс добавлена
  сверка всех пяти денежных тайлов тайл-в-тайл между `/dashboard` и
  `/id-folders` (раньше сравнивалась только одна пара по разным
  подписям — теперь именно то, что требует §3, автоматизировано).
- `tools/functional_test.py`: сценарий `test_id_folders_money_clarity_tiles`
  проверял наличие удалённых тайлов — переписан на проверку присутствия
  всех пяти новых.

Клик по всем пяти стадиям трубы + «Неподписано», фактический подсчёт
строк на `/id-folders?status=…` (через `fetch`, не считая заглушку «нет
папок»):

| Стадия | `status=` | Труба показывает | Строк в таблице |
|---|---|---|---|
| Сформировано папок | `formed` | 19 | 19 |
| На проверке | `checking_all` | 1 | 1 |
| Подписано | `awaiting_smeta` | 0 | 0 |
| Текущая КС-2 | `ks2` | 0 | 0 |
| Следующая КС-2 | `ks2_next` | 0 | 0 |
| (отдельное значение) | `not_signed` | — | 20 |

Легаси-алиасы проверены отдельно: `status=transferred` → 1,
`status=checking` → 0 (в сумме с `transferred` дают ровно 1 — то же
множество, что и `checking_all`), `status=signed` (бывшая прямая ссылка
реестра) → 0, теперь **отфильтровано**, не все 20. Редирект:
`/id-folders/registry?status=signed&sort=asc` → 301 →
`/id-folders?status=signed&sort=asc` → страница пришла отфильтрованной
(0 строк, не 20) — критерий §6.5 выполнен.
