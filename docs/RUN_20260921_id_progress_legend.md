## §1 — семантика трёх цветов/чисел, проверено вживую

`compute_id_progress_stream()` (`backend/main.py:4426`) считает последнюю запись
на связку «раздел + вид работы» (`distinct on (row_id, work_type_id)`, только где
`work_type_id is not null`):

- **зелёный** — `status_code = 'Подписано'`;
- **жёлтый** — весь цикл РСК (`RSK_CYCLE_STATUS_CODES`: Первичная проверка РСК,
  Устранение замечаний 1, Повторная проверка РСК, Устранение замечаний 2) плюс
  `Подписано в карандаше`;
- **красный** — всё остальное, что не подходит под два условия выше.

Проверено скриптом `check_stream.py` (запущен в контейнере, удалён после
проверки):

```
tiles['total_pairs']           = 2872
sum(green_n+yellow_n+red_n)    = 2872
разница                        = 0
```

Отдельно проверен вопрос §1 задания — связки вовсе без записи о статусе:

```
пар (строка существует) без status_id, исключая вкладки opv/n: 222
```

Эти 222 связки не попадают ни в один из трёх фильтров стрима — `LEFT JOIN`
оставляет `s.code = NULL`, а `NULL <> 'Подписано'` и весь список сравнений в
`RSK_CYCLE`/`'Подписано в карандаше'` дают `NULL`, не `TRUE`, так что красный
фильтр (`s.code <> ... and <> all(...)`) их тоже не берёт. Подтверждено и
теоретически (семантика SQL `NULL`), и вживую (222 = разница между
`total_rows_all`-производной величиной и суммой трёх чисел по факту связок).
Легенда содержит это явно: «связки без единого статуса ни в одно из трёх не
входят».

## §3 — две легенды на одной странице используют одни цвета для разного

| цвет | «Поток по вкладкам» (новая легенда) | «Матрица „Раздел × Этап"» (существующая легенда) |
|---|---|---|
| зелёный | `Подписано` | `Подписано` (`_id_matrix_cell_color`: `status_code == 'Подписано'`) |
| жёлтый | весь цикл РСК (4 статуса) + `Подписано в карандаше` | **только** `Первичная проверка РСК` — остальные 3 статуса цикла РСК (Устранение замечаний 1/2, Повторная проверка) вообще без цвета в матрице |
| красный | всё остальное (по исключению) | только `Другая блокирующая причина` — конкретная причина блокера/стоппера, не «остальное» |
| синий | — (не используется в этой легенде) | только `Нет проектного решения` — единственная причина блокера/стоппера, дающая синий |

Совпадает только зелёный. Жёлтый и красный называют разные множества
статусов под одним и тем же цветом; синий существует только у матрицы.
Каждая легенда сама по себе однозначна (обе явно перечисляют, что именно
стоит за каждым цветом), но читатель, выучивший цвета по одной, неверно
прочитает другую — это и есть находка задания.

**Рекомендация координатору.** Выравнивать имеет смысл стрим к матрице, а не
наоборот: цветовая схема матрицы информативнее — она различает «в процессе
цикла РСК» (жёлтый, только начальный шаг) от «стоит из-за конкретной, ещё не
решённой причины» (красный/синий по типу причины), тогда как стрим сворачивает
всё это в одну грубую категорию «жёлтый = где угодно в цикле РСК плюс
подписано в карандаше». Схлопывать различие матрицы до грубости стрима
означало бы потерять сигнал, который сейчас есть только в матрице (какая
именно причина блокирует раздел). Обратное — научить стрим различать «только
первый шаг цикла» от «остальные шаги цикла» и завести отдельный цвет под
`Подписано в карандаше` — обошлось бы без потери информации ни на одной из
двух панелей. Менять цвета матрицы в рамках этого задания не входило в
задачу и не делалось; обе легенды сейчас корректно и однозначно описывают
свою панель по отдельности.
