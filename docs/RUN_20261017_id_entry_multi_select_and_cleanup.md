## Правка 1 — /id-entry «Новая запись»: мультивыбор разделов и видов работ

- `id_entry.html`: `f-row` и `f-work-type` — `multiple` (size 8/6),
  подписи полей объясняют Ctrl+клик и «пусто = без вида работ».
- Принципиальное решение (из анализа, координатору доложено): разделы
  выбираются только в пределах ОДНОЙ вкладки — статус и справочники
  привязаны к вкладке, общий статус для разных вкладок не определён.
  Попытка выбрать разделы другой вкладки: лишнее снимается с выбора
  автоматически, над формой показывается уведомление с именем вкладки.
- Автоподстановка прежних данных (п.1 докса «Вопросы к базе», 06.09)
  работает только при РОВНО одном выбранном разделе (и не более одного
  вида работ) — к чему применять чужие прежние значения при нескольких,
  не определено; при множественном выборе поля остаются как заполнено.
- Отправка: `row_ids`/`work_type_ids` через запятую; подтверждение
  `window.confirm` при более чем 50 комбинациях.
- `main.py` `api_id_entry_create`: сигнатура расширена
  `row_ids`/`work_type_ids` (одиночные `row_id`/`work_type_id`
  сохранены для совместимости); жёсткий потолок 200 комбинаций;
  валидация каждого id на принадлежность вкладке; одна транзакция на
  весь набор (либо всё, либо ничего); на каждую комбинацию — прежний
  путь целиком: автоблокировка по стоп-фактору с дедупликацией,
  audit_log на запись. Ответ: `{"ok": true, "id": <первый>, "created":
  N, "ids": [...]}` — поле `id` оставлено для старых клиентов.
- Клик по строке реестра по-прежнему открывает её в форме — сбрасывает
