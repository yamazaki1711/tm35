## Пункт 6a — РСК «Снятые»: механизм исправен, находка — честный ноль

Прочитан весь путь: дропдаун (`rsk_registry.html`, значения `active`/
`closed`/пусто) → `rsk_registry_page()` (`state=='closed'` → `where not
v.is_active`, механизм корректен) → закрытие пишется в
`rsk_import_confirm()` (`update rsk_violation set is_active=false,
closed_in_act_id=%s where sys_no = any(%s)` — для нарушений, отсутствующих
в новом акте). Прямой SQL на 24.09.2026: **1 акт** в `rsk_act` (№4183-159
от 11.08.2026), **0** нарушений с `is_active=false`. Другими словами — ни
разу не было ВТОРОГО акта, с которым можно было бы сравнить первый и
кого-то закрыть; фильтр «Снятые» механически не может найти закрытых
нарушений, потому что их пока структурно не существует, а не потому что
сломан.

**Доказано, не только продекларировано** — живой скрипт внутри ОТКАЧЕННОЙ
транзакции (`rollback`, ничего не осталось в БД): взял 3 реальных
активных нарушения (`sys_no` 3, 6, 11), симулировал их закрытие «вторым
актом» (ровно так же, как это делает `rsk_import_confirm()`), выполнил
ТОТ ЖЕ SQL, что строит `state='closed'` в `rsk_registry_page()`, —
запрос вернул ровно эти 3 `sys_no`, ни одного лишнего/недостающего.
Механизм работает корректно, если/когда появится второй акт. Экран
`/rsk?state=closed` на живых данных — «Найдено: 0», честно (скриншот).

**Настоящая причина найдена одна: `/gantt` открывался НЕ на сегодняшней

1. `api_gantt()` — дефолт (без параметра `start`) был `get_display_window()[0]`

   передаёт `display_window_start_iso` во фронтенд, а `gantt.html`
   инициализирует `state.start` ИМЕННО этим значением и всегда шлёт его
   явным параметром `start` в первом же запросе к `/api/gantt` — то есть
   ветка «start не передан» в `api_gantt()` при обычном открытии
   страницы **вообще не исполняется**. Правка №1 в `api_gantt()`
