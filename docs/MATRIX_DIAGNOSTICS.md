# Диагностика природы календарной матрицы — 15.08.2026

Вопрос: матрица «План» по дням в Excel — график работ (плановое окно
выполнения) или ресурсная разнарядка (куда завтра поставить людей)?
От ответа зависит интерпретация всей дальнейшей аналитики (отставание
работы vs недопоставка ресурса — это разные вещи, см. `analytics.py`).

Тесты прогнаны на 80 работах (из 163), у которых вообще есть хоть один
день с `planned_crew > 0` в `daily_progress` (`source='excel_import'`) —
скрипт `deploy/matrix_diagnostics.py`, воспроизводимо через тот же
SSH-туннель, что и остальной импорт.

## Результаты

| Тест | Результат | Вывод |
|---|---|---|
| 1. Непрерывность | 76 из 80 (95%) — один сплошной блок плановых дней (выходные не считаются разрывом) | **За график** |
| 2. Фрагментация | среднее 1.05 блока/работу, медиана 1.0, максимум 2 (у 4 работ) | **За график** |
| 3. Сверка с «Месяц выполнения работ» | 73 из 73 работ, где оба источника есть — совпадение месяца 100% | **Сильно за график** (подтверждающий тест, независимый в объёме, в котором заполнен — planировщик указывал месяц отдельно от матрицы) |
| 4. Трудоёмкость (ΣПлан чел-дн.) vs объём работ | коэффициент корреляции Пирсона 0.44 | **Умеренно за график** (не 0, но и не близко к 1 — не считаю это опровержением, объём в разных единицах измерения по разным работам плохо сопоставим напрямую) |
| 5. Край горизонта планирования | максимум 6.2% работ (5 из 80) разделяют одну дату последнего планового дня, даты разбросаны по июлю-октябрю, не концентрируются на конце захваченного окна (ноябрь) | **Артефакта усечения НЕ обнаружено** |

## Вывод

Календарная матрица «План» — это **график работ** (`matrix_schedule`),
не ресурсная разнарядка, с высокой уверенностью для всех 80 работ, где
она заполнена (все 5 тестов согласованно указывают в одну сторону, ни
один не противоречит). Отклонение факта от плана в этих работах
интерпретируется как **отставание по срокам**, а не только как
недопоставка ресурса — но недопоставка ресурса (план людей на день vs
факт людей на день) остаётся отдельной, дополняющей метрикой, не
заменяется одной цифрой (см. Задачу 43).

## Проставлено в БД

- `baseline_source='matrix_schedule'` — 80 работ (есть календарные данные).
  - `confidence='high'` — 76 работ (1 сплошной блок).
  - `confidence='medium'` — 4 работы (2 блока: возможна пауза в работе,
    не считаем это высокой уверенностью в точности окна).
- `baseline_source='text_month_only'`, `confidence='low'` — работы, где
  есть только текстовое поле «Месяц выполнения работ» без календарных
  данных (единственный источник, не перепроверяется).
- `baseline_source='no_data'`, `confidence='none'` — у остальных работ
  baseline не восстановлен ни из одного источника.

**Ни одна работа не исключена по признаку «край горизонта планирования»**
— тест 5 не выявил кластеризации, признак не сработал ни для одной
работы.

## Двойной счёт ресурса между листами (проверено отдельно)

Разбивка факта людей по дням (1-13.08.2026) по источнику: **main ~14-17
чел./день, aux ~3-6 чел./день, iks/rsk — 0** (у этих двух листов вообще
нет календарных данных с фактом людей — заполнены только текстом
описаний замечаний). Риск задвоения существует только между main и aux
теоретически.

Вывод: **не задвоение**. ТЗ 8.6 прямо определяет долю вспомогательных
работ как `AuxFactHours / TotalFactHours` — то есть по замыслу ТЗ main и
aux суммируются в общий ресурс, aux — его часть, а не отдельный контур.
Складывать main+aux в «Итого людей» — не ошибка, а то, что и требуется.
iks/rsk безопасны по построению (нечего задваивать — там 0 фактических
человеко-дней в календаре). Правдоподобность: ~20 чел./день на объекте
не противоречит порядку величины из нарратива ТЗ («12 доступно» в более
раннем состоянии проекта, до роста).

## Что не проверено (честно)

- Тест 4 (корреляция) — умеренный, не окончательный сигнал сам по себе;
  вывод сделан по совокупности всех пяти тестов, не по нему одному.
- Диагностика не проверяет, что «график» составлен верно (реалистичность
  сроков) — только то, что данные ВЕДУТ СЕБЯ как график, а не как
  разнарядка. Подтверждение планировщиком по-прежнему требуется, но
  теперь только для работ с `confidence != 'high'` — это меньший объём
  ручной сверки, чем весь список.
