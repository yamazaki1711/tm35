# Хабаровское время сквозь весь проект + повторная проверка формы факта

Решение координатора 29.08.2026: весь `tm.asd-kontur.ru` живёт по
Asia/Vladivostok (UTC+10) — «сегодня», даты форм, просрочки, окна,
отображаемое время. Срочность — до понедельника (01.09.2026 начинается
ежедневное заполнение по регламенту «до 11:00 за вчера»). Конвенция
отчёта — ПРОВЕРЕНО / НЕ ПРОВЕРЕНО / ПРЕДПОЛОЖЕНИЕ.

## 1. Часовой пояс — сквозное применение

### 1.1. Найдено и переведено (полный список правок)

**ПРОВЕРЕНО.** Сплошной `grep` по `main.py` на
`date.today()/now()/current_date` (не `updated_at=now()` — это
корректная отметка момента записи, хранение не менялось) дал, кроме
уже переведённого раньше, ещё:

- `/data` (хаб «Данные») — счётчик просроченных baseline считал
  `plan_finish < current_date` (SQL, часовой пояс сессии Postgres —
  проверено `show timezone` = `Etc/UTC`, то есть тот же класс ошибки).
  Переведено на `plan_finish < %s` с `object_today()` из Python.
- **Показ времени** (не даты — это отдельный, не пойманный в прошлый
  раз класс бага): `updated_at`/`created_at` — колонки `timestamptz`,
  БД хранит их в UTC (проверено: `select now()` вернул
  `...+00:00`/`UTC`). Прямой `.isoformat()`/`.strftime()` на таком
  значении печатает UTC-цифры как есть. Введена единая функция
  `to_object_tz(dt)` (конвертирует в `object_timezone()` перед
  форматированием, хранение не трогает) и применена в:
  - `_dmy` (Jinja-фильтр для дат по всему сайту) — теперь пересчитывает
    время, если у значения есть `.hour` (голые `date`-колонки не
    трогает — они уже трактуются как хабаровские сутки, менять нечего);
  - `_csv_dmy` (та же логика для выгрузок CSV);
  - JSON-ответы `/api/shift`, `/api/shift/cell`, `/api/work-detail`
    (поле `updated_at`, показывается на `/shift`/`/form` как «изменено
    ДД.ММ.ГГГГ ЧЧ:ММ»).
  - **Найден и исправлен попутно баг того же класса** в
    `today.html:73` — `{{ b.created_at.strftime('%d.%m.%Y') }}`
    напрямую в шаблоне, в обход фильтра `_dmy` (единственное такое
    место, проверено `grep` по всем шаблонам на `strftime`/
    `.isoformat()`) — заменено на `{{ b.created_at|dmy }}`.
- **Клиентский JS** — `datepicker.js` (общий виджет календаря на ВСЕХ
  страницах с датой) и `/gantt` брали «сегодня» через браузерный
  `new Date()`, то есть по часовому поясу ЗРИТЕЛЯ, не объекта —
  реальный риск, если координатор смотрит дашборд не из Хабаровска.
  Введено: `render()` в `main.py` теперь кладёт `object_today_iso` в
  контекст КАЖДОГО шаблона (`ctx.setdefault`, не на каждый route
  отдельно — чтобы не забыть на новой странице), `base.html` публикует
  его как `window.TM35_OBJECT_TODAY`. `datepicker.js` (подсветка
  «сегодня» в календаре, дефолтный месяц при открытии без значения) и
  `/gantt` (кнопка «Сегодня», окно по умолчанию при первой загрузке)
  теперь читают это значение вместо `new Date()`.

## 4. Моделирование 08:00 / 10:30 / 23:00 по Хабаровску

**ПРОВЕРЕНО** (расчёт вне контейнера тем же алгоритмом, что
