## §2 — правка: паддинг ячейки .85rem → .5rem, сайтово

`backend/static/style.css`, правило `th, td` (общее для каждой таблицы
сайта, не `.data-table`-специфичное) — горизонтальный паддинг снижен с
`.85rem` до `.5rem`; вертикальный (`.65rem`) не менялся. Проверено
живьём сразу после правки: `/rsk` — `scrollWidth` = `clientWidth` =
1310, overflow **0**.

`td.nowrap { width: 1% }` не пробовал — задание уже показало, что это
не работает (нечего перераспределять, каждая колонка уже на минимуме),
подтверждено собственным измерением выше.

## §4 — два новых правила в `tools/ui_audit.py`

**`table_overflow`** — для каждой таблицы: `table.scrollWidth >
containerWithOverflowX.clientWidth` → находка с именем страницы,
номером таблицы и переполнением в px. Провальная (`fatal: true`) везде,
**кроме** списка `TABLE_OVERFLOW_ALLOWED_ROUTES` — `/gantt`, `/shift`,
`/id-progress` (три страницы, уже названные исключением в CLAUDE.md §7:
«сетка… прокручивается сама») плюс `/id-grafik/category-mapping`
(найдена этой же проверкой, той же формы — колонка на категорию — но
CLAUDE.md её не называет; оставлена информационной, не провальной, до
решения координатора — см. ниже). `/baseline`/`/form` — чистые
редиректы на `/shift`, попадают в тот же список по той же причине.

**`column_over_allocated`** — для каждой колонки: allocated шире, чем
content (натуральная ширина, та же методика §1) + двойной паддинг +
4px допуска → находка, информационная (не проваливает прогон) —
использована в §1 для доказательства, что на `/rsk` такой колонки нет,
не для гейта самого по себе (на сайте много честной, неопасной слабины
у таблиц, которые и так помещаются — раздувать это в провал значило бы
шуметь без причины).

Рост `column_over_allocated` после правки — ожидаемый и безопасный
побочный эффект: меньший паддинг оставляет больше свободного места в
уже помещающихся таблицах, auto-layout браузера распределяет его между
колонками пропорционально — это не новый дефект, тот же механизм,
которым таблица вообще заполняет 100% ширины блока. На `/rsk` таких
находок по-прежнему 0.

`small_font`/`container_width`/`short_row` — без изменений (2697/126/6
и до, и после — правка не трогала шрифт и не меняла структуру страниц).
