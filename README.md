# ТМ-35 — мониторинг СМР и контур ИД

Подсистема мониторинга строительно-монтажных работ и исполнительной
документации по объекту «Тепломагистраль-35» (г. Хабаровск, заказчик
ООО «ИКС-Хабаровск»). Backend на FastAPI + Jinja2, PostgreSQL.

Живой стенд: https://tm.asd-kontur.ru (Basic Auth).

## Контур ИД — что реализовано (по состоянию на 04.09.2026)

Единица учёта — **раздел** (`id_form_row`, строка вкладки Excel из 15
категорий-справочников ПТО), не «пакет» — пакет-агрегат появляется
позже, при сборке в папку.

- **Ввод по разделам** (`/id-entry`) — каскад «Ответственный → Раздел
  (сгруппирован по категориям) → Вид работ → Статус (9 значений,
  единый справочник `id_form_status`) → даты → Стоп-фактор → Подписант
  РСК → Комментарий». Блокировка раздела на ИЗМ — отдельная мини-форма.
- **Разделы ИД** (`/id-packages`) — сводный реестр всех разделов с их
  текущим статусом (по последней записи в форме ввода), не пакетов.
- **Выполнение** (`/id-folders`) — сборка папок из подписанных разделов:
  создание папки (авто-номер или своё имя, дата задним числом), состав
  10–100 разделов (мягкая подсказка, не жёсткая блокировка), сумма за
  раздел 10 000,00–500 000,00 ₽, передача в СДО с ФИО подписанта. Один
  раздел — не более чем в одной папке (ограничение на уровне схемы БД).
- **Реестр изменений ПД/РД** (`/changes`, бывш. «ИЗМ») — шифр раздела,
  статус (2 значения: «В работе у проектировщика» / «Техрешение
  получено»), инициатор фиксирован как ССР (подрядчик).
- **Предписания РСК** (`/prescriptions`) — загрузка PDF-документа на
  сервер (не внешняя ссылка), еженедельная сводка устранения (живой
  пересчёт при заходе на страницу — push-рассылки нет).
- **Дашборд** (`/dashboard`) — строго разделён на «Обзор СМР» (верх
  страницы) и «Обзор ИД» (низ), без чередования секций.

## Структура репозитория

- `backend/` — FastAPI-приложение (роуты, шаблоны, статика, Dockerfile)
- `migrations/` — SQL-миграции схемы БД `tm35`, по порядку номеров
  (до `021` включительно; схемные правки контура ИД после 03.09.2026 —
  `id_folder`/`id_folder_row`/`id_manual_volume`, `id_form_responsible`,
  `prescription.document_file_path` — применены на живой БД, но пока не
  оформлены отдельными файлами здесь, актуальную схему см. в БД или в
  `KNOWN_ISSUES.md`)
- `deploy/` — nginx-конфиги поддомена и вспомогательные скрипты
- `tools/` — служебные скрипты (аудит, функциональные проверки)
- `docs/` — техническая документация: разбор данных, схема ИД-контура,
  журналы реинжиниринга, справочники ГЭСН/ССР
- `CLAUDE.md` — постоянный контекст проекта для Claude Code (архитектура,
  находки, история решений)
- md-файлы в корне и `280826/` — брифинги и отчёты по итогам сессий
  (снимки состояния на конкретную дату, не источник истины по коду)

## Деплой

Код на сервере (`kat-core`, контейнер `tm_backend`) обновляется **без
git** — файлы копируются в образ (`docker cp`), `main.py` требует
`docker restart tm_backend`, шаблоны `.html` подхватываются на лету.
Этот репозиторий — снимок кода, не источник деплоя.

## Что не включено

Служебные секреты (`.secrets/`), справочные материалы большого объёма
(ЕНиР, импортируемые Excel-графики, исходные ТЗ) и артефакты визуальной
приёмки (скриншоты) в репозиторий не включены — только код и
документация.
