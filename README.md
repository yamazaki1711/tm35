# ТМ-35 — управление стройкой: СМР, исполнительная документация, строительный контроль

Подсистема управления строительством объекта «Тепломагистраль № 35 от
Хабаровской ТЭЦ-3, г. Хабаровск» (заказчик ООО «ИКС-Хабаровск»).
Backend на FastAPI + Jinja2, PostgreSQL, фронт без сборщиков — серверные
шаблоны и ванильный JS (работа с планшета в том числе).

Живой стенд: https://tm.asd-kontur.ru — публичный просмотр, запись под
логином (`/login`), точка входа `/` — редирект на `/dashboard`.

Система ведёт **единую базу данных трёх контуров** и связи между ними.
Цепочка управления: *изменение ПД/РД → предписание надзора → устранение
(СМР) → подписание ИД → закрытие акта (КС-2/КС-3)*.

## Контур СМР — строительно-монтажные работы

- **Смена (день целиком)** (`/shift`) — ввод факта по работам и
  численности за день, плановые сроки на той же странице. Старые
  маршруты `/form` и `/baseline` отвечают редиректом сюда.
- **Стоп-фактор** (`/blockers`) — причины простоя с ответственными и
  дедлайнами, экспорт CSV.
- **Успеваем?** (`/status`) — S-кривая план/факт, прогноз завершения,
  история пересчётов.
- **Люди ↔ срок** (`/calculator`) — калькулятор: сколько людей нужно,
  чтобы уложиться в срок (и наоборот).
- **Сегодня** (`/today`), суточный **Рапорт** (`/report`),
  **График производства работ** (`/gantt`, интерактивный Гантт с
  редактированием ячеек), **Причины простоя** (`/losses`),
  справочные разделы (материалы, субподрядчики, нормы ГЭСН/ССР,
  ограничения), журнал (`/journal`).

## Контур ИД — исполнительная документация

Единица учёта — **раздел** (`id_form_row`). Термин «вкладка» — от
исходного Excel-формуляра ПТО: 17 вкладок-категорий, единый справочник
статусов `id_form_status` (10 значений, включая «Подписано в
карандаше»).

- **Ввод по разделам** (`/id-entry`) — каскад «ответственный → раздел →
  вид работ → статус → даты → стоп-фактор → подписант РСК», блокировка
  раздела на ИЗМ.
- **Разделы ИД** (`/id-packages`) — сводный реестр разделов с текущими
  статусами и фильтрами, экспорт CSV.
- **Прогресс по видам работ** (`/id-progress`) — цветовые полосы по
  вкладкам и видам работ, дрилдаун до разделов, «поток по вкладкам».
- **Выполнение (папки)** (`/id-folders`, реестр `/id-folders/registry`)
  — сборка папок из подписанных разделов, сумма на папку целиком,
  отметки подписей, **КС-3** (`/api/ks3-entry`), массовый ввод
  (`/id-folders/bulk-entry`), передача в СДО.
- **График ИД** (`/id-grafik`) — покраска разделов по статусам на
  графике производства работ, категориальный маппинг, экспорт XLSX.
- **Реестр изменений ПД/РД** (`/changes`) — шифр раздела, статус
  («В работе у проектировщика» / «Техрешение получено»), инициатор ССР.
- **Связь с надзором** (`/id-rsk-link`) — привязка раздела ИД к
  предписанию РСК (звено цепочки закрытия).
- Ручные объёмы (`/api/manual-volume`) и мета реестров.

## Контур РСК — строительный контроль заказчика

- **Загрузка акта** (`/rsk/import`) — импорт PDF-акта проверки
  (`rsk_parser.py`, pdfplumber): предпросмотр распознанных замечаний,
  подтверждение перед записью, защита от повторной загрузки.
- **Реестр замечаний** (`/rsk`) — карточка замечания
  (`/rsk/violation/{sys_no}`), статусы устранения, reopen/reclose.
- **Отработка предписаний** (`/rsk/processing`) — назначение
  ответственных и сроков, единый ответственный по замечанию.
- **Обзор РСК** (`/rsk/dashboard`) — плитки по состояниям и отделам.

## Дашборд и данные

`/dashboard` — «Обзор СМР» (выполнение, прогноз срока, просрочки),
«Обзор ИД» (деньги с НДС: контракт, подписано по КС-3, подписано ИД,
невыбираемый остаток, остаток; статусы АОСР; папки; активные ИЗМ) и
«Обзор РСК» (замечания по состояниям). `/data` — свежесть данных по
разделам системы, `/quality` — контроль качества данных.

Доступ: публичное чтение, запись — по точечным правам: `smr:write`,
`id-folders:submit`, `changes:submit`, `prescriptions:submit`,
`rsk:submit`, `id_tab:<код>`, группы `zone:id` / `zone:smr`, роль
`admin`. Управление пользователями — `/settings/users`.

## Структура репозитория

- `backend/` — FastAPI-приложение: роуты (`main.py`), шаблоны,
  статика, парсер актов РСК, синхронизация погоды, Dockerfile
- `migrations/` — SQL-миграции схемы БД `tm35`, `001`–`044`, по
  порядку номеров
- `deploy/` — nginx-конфиги поддомена, вспомогательные скрипты
- `tools/` — служебные скрипты (аудит, функциональные проверки,
  импорт графики ИД)
- `import/` — парсеры и исходные данные: Excel-графики, свод tables
  ПТО, ЕНиР/ГЭСН (PDF), выгрузки РСК
- `docs/` — техническая документация. `docs/STATE.md` — текущее
  состояние проекта (читается первым, при расхождениях верен он);
  `RUN_*.md` — журналы сессий с датами; разборы данных, схема ИД-контура,
  справочники ГЭСН/ССР
- `KNOWN_ISSUES.md` (корень) — накопленные находки и готчи, нумерованный
  журнал
- md-файлы в корне (`TM35_*.md`) — брифинги и отчёты конкретных сессий,
  снимки состояния на дату, не источник истины по коду

## Деплой

Код на сервере (`kat-core`, контейнер `tm_backend`) обновляется без
git — файлы копируются в образ (`docker cp`), `main.py` требует
`docker restart tm_backend`, шаблоны `.html` подхватываются на лету.
Этот репозиторий — снимок кода; о возможном расхождении прода и
`origin/main` см. `docs/STATE.md` и `KNOWN_ISSUES.md` (§75).

## Что не включено

Служебные секреты (`.secrets/`) и артефакты визуальной приёмки
(скриншоты прогонов) в репозиторий не включены. Исходные Excel/PDF
(графики, реестры нарушений, ТЗ, ЕНиР/ГЭСН) включены в `import/` и
`docs/` как данные, на которых строился импорт.
